请基于当前已经整理好的纯 Python 项目 `SphinGOlipID_project_pyonly_v0.2` 继续开发 GUI 和后续功能模块。当前项目已经完成 notebook 到 `.py` 的初步转换，后续开发重点是：完善后端算法模块、统一数据接口、搭建 GUI 原型，并为后续桌面软件封装做准备。

# 一、总体开发目标

将当前纯 Python 项目发展成一个完整的 SphinGOlipID 鞘脂自动注释工具。

项目的核心功能包括：

1. 理论一级分子式库构建；
2. MS1 候选结构检索；
3. 规则驱动 MS/MS 碎片匹配；
4. MS2 注释结果评分与排序；
5. RT 校正与 RT-based validation；
6. 注释结果去重与清理；
7. 最终注释结果导出；
8. GUI 界面操作；
9. 图表可视化；
10. 后续桌面软件打包。

当前最重要的是：**不要重写 MS2 匹配算法逻辑**，只做接口整理、参数化、错误修复、模块连接和 GUI 封装。

优先处理以下文件：


需要完成：

1. 检查所有函数输入输出；
2. 删除剩余硬编码路径；
3. 所有参数通过 config 或函数参数传入；
4. 所有模块返回标准 DataFrame 或标准结果对象；

所有 GUI、CLI、测试都应该调用这个统一 config。

# 三、MS2 匹配模块完善计划

MS2 匹配是当前核心模块，逻辑不要大改。

需要重点完成：

## 1. 输入文件检查

运行前检查：

1. MS/MS txt 文件是否存在；
2. precursor target Excel 是否存在；
3. MS1 theoretical library 是否存在；
4. 输出目录是否可写；
5. Excel 中必要列是否存在；
6. m/z、RT、intensity 是否能转成数值。

如果缺少必要列，需要明确报错，例如：

```text
Missing required column: Precursor m/z
Missing required column: RT
Missing required column: Formula
```

## 2. MS2 数据读取标准化

需要将 MS2 txt 文件读取结果统一为 DataFrame，建议字段为：

```text
file_name
scan_id
precursor_mz
rt
fragment_mz
fragment_intensity
```

不同来源的 MS2 txt 文件格式可能略有差异，因此读取函数需要尽量稳健。

## 3. 候选结构检索

根据 precursor m/z 从理论 MS1 library 中检索候选。

需要支持：

```text
precursor_mz
ppm_tolerance
ion_mode
adduct
lipid_class
```

输出候选 DataFrame，字段建议包括：

```text
candidate_id
lipid_name
lipid_class
formula
adduct
theoretical_mz
observed_mz
ppm_error
```

## 4. 理论 MS/MS 碎片生成

保留现有规则，只整理接口。

建议函数形式：

```python
generate_theoretical_fragments(candidate: dict) -> pd.DataFrame
```

输出字段：

```text
fragment_name
fragment_type
fragment_formula
theoretical_mz
evidence_level
description
```

其中 `fragment_type` 可以包括：

```text
diagnostic
headgroup
lcb
fatty_acyl
glycan
neutral_loss
```

## 5. 碎片匹配

匹配实测 MS/MS 和理论 MS/MS。

建议函数形式：

```python
match_fragments(
    observed_fragments: pd.DataFrame,
    theoretical_fragments: pd.DataFrame,
    ppm_tolerance: float,
    min_intensity: float,
) -> pd.DataFrame
```

输出字段：

```text
observed_mz
observed_intensity
theoretical_mz
fragment_name
fragment_type
ppm_error
matched
```

## 6. 评分与排序

保留原评分体系。

但需要把评分输出标准化：

```text
matched_fragment_count
matched_intensity_sum
total_fragment_intensity
matched_intensity_ratio
ms2_match_score
rank
```

每个 precursor 默认保留 top 3 candidates。

# 四、RT validation 模块开发计划

RT 模块用于辅助验证 MS2 注释结果，不替代 MS2 匹配。

目标是实现文章中的：

```text
RT series extraction + RANSAC fitting + RT-based validation
```

## 1. 输入

输入 MS2 注释结果表，至少包含：

```text
lipid_name
lipid_class
observed_rt
carbon_number
double_bond
hydroxyl_number
ms2_match_score
```

如果当前结果表没有这些结构字段，需要先写解析函数，从 lipid name 中解析。

## 2. 同系物系列提取

根据 lipid class、LCB 类型、脂肪酰基特征提取 homologous series。

建议字段：

```text
series_id
lipid_class
base_structure
carbon_number
double_bond
hydroxyl_number
observed_rt
```

## 3. RANSAC RT 模型

使用 RANSAC 建立 RT 趋势模型。

功能：

1. 根据同系物系列拟合 RT；
2. 预测 predicted_rt；
3. 计算 rt_error；
4. 计算 relative_error；
5. 标记 outlier。

输出字段：

```text
observed_rt
predicted_rt
rt_error
relative_error
rt_validation_status
```

`rt_validation_status` 建议分为：

```text
pass
warning
outlier
not_evaluated
```

## 4. RT 模块输出

输出两个文件：

```text
rt_validation_results.xlsx
rt_series_summary.xlsx
```

同时为 GUI 提供绘图数据：

```text
predicted_vs_observed
rt_error_distribution
series_fit_data
```

# 五、result_cleaning 去重模块开发计划

该模块用于最终注释表清理。

## 1. 去重逻辑

根据以下信息判断是否重复：

```text
lipid_name
observed_mz
observed_rt
adduct
sample/file
```

默认 tolerance：

```text
m/z tolerance: 0.01 u 或 10 ppm
RT tolerance: 5 s
```

需要做成可配置参数。

## 2. 保留规则

重复结果中优先保留：

1. MS2 score 最高；
2. 匹配碎片数更多；
3. RT validation 通过；
4. ppm error 更小；
5. signal intensity 更高。

但是要注意：不能误删真正的同分异构体。如果 RT 差异明显，应该保留为不同 isomer candidate。

## 3. 输出

输出：

```text
final_annotation_table.xlsx
deduplication_report.xlsx
class_summary.xlsx
sample_summary.xlsx
```
